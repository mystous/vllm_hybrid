# TSK_056 — "AMX Small-K All-Pairs Primitives": MP + correlation + kNN 통합 (넓고 야심차게)

*생성 2026-06-18. 타깃: 시스템(OSDI/ATC) 또는 DB(SIGMOD/VLDB) — "AMX가 small-K all-pairs 연산의 범용 엔진"이라는 폭 있는 주장. 근거 실측 = `/home/mystous/newidea/`.*

## 0. 한 줄 요약
**짧은 contraction-dim(K=윈도우/특징)의 all-pairs dot-product 행렬**(matrix profile·correlation/Gram·exact kNN·유사도 self-join)은
일반 BLAS가 못 살리는 **Intel AMX의 sweet spot**임을 보이고, 단일 통합 커널(AMX-bf16 blocked GEMM + 사전정규화)로
**여러 도메인에서 SOTA(STUMPY·fp32-BLAS·FAISS)를 능가**한다는 폭 있는 주장. TSK_055(MP)의 일반화.

## 1. 아이디어 (왜 신규·왜 폭)
- 공통 커널: `G = X·Xᵀ`(N×N, contraction K). MP·correlation·cosine-kNN·kernel(Gram)·유사도조인이 모두 이 형태.
- **핵심 관찰(실측)**: 일반 BLAS(OpenBLAS)는 큰 square GEMM은 3.9 TFLOP/s지만 **작은-K(tall-skinny) shape선 56~109 GFLOP/s로 급락**(낮은 arithmetic intensity·memory-bound). 반면 **AMX는 16×K 타일 구조 + 블로킹으로 작은-K서도 4~16 TFLOP/s** 유지 → 이 regime의 지배 엔진.
- **주장**: "all-pairs similarity primitives의 병목은 작은-K GEMM이고, 그것은 AMX가 BLAS·전용 SOTA를 역전하는 영역이다." MP는 그 첫 사례, correlation/kNN으로 일반화.
- **신규성**: AMX를 이 primitive class에 매핑한 선행 0편. 각 도메인 SOTA(STOMP/FAISS-flat)는 행렬엔진 미활용 or fp32.

## 2. 분야별 SOTA
| Primitive | 도메인 | SOTA | 행렬엔진/정밀도 | 우리 차별 |
|---|---|---|---|---|
| matrix profile | 시계열 DM | STUMPY/SCAMP(STOMP O(n²)) | ✗ / fp32 | AMX-GEMM 2.6~100× |
| pairwise correlation/Gram | 통계·유전체·금융 | BLAS sgemm | ✗AMX / fp32 | 작은-K서 AMX 20~123× |
| exact kNN/유사도 self-join | 검색·dedup·RAG | FAISS IndexFlat(BLAS), brute-force | fp32 / (ANN=HNSW sublinear) | AMX-bf16 exact, recall@10 0.99 |
| kernel methods(NTK/GP) | ML | BLAS Gram | ✗AMX | CPU서 백만-스케일 |
- **주의**: ANN(HNSW)은 sublinear라 brute-force가 짐 → **exact/all-pairs가 필요한 경우만** 우리 영역(dedup·정확 kNN·전체 거리행렬). 경계 명시.

## 3. 우리 방식 (통합 커널 + 도메인 어댑터)
1. **공통 코어**: AMX-bf16 blocked GEMM `X·Xᵀ`(VNNI pack·fused tile→reduce·B-panel L2 블로킹·OpenMP) — TSK_055 코어 재사용.
2. **사전정규화**: z-norm(MP/correlation)·L2-norm(cosine kNN) → cancellation 제거, bf16 정확도 보존.
3. **도메인 어댑터(reduce 단계만 교체)**: MP=행별 min+exclusion; correlation=행렬 출력; kNN=행별 top-k; dedup=임계 초과 쌍.
4. **정밀도 모드**: bf16(기본)·INT8(스케일링, 천장 10×)·정확도 게이트별 선택.

## 4. 검증 방법 (도메인별)
- **MP**: vs STUMPY/SCAMP (TSK_055 그대로).
- **correlation/Gram**: vs OpenBLAS fp32 sgemm — K-sweep(64~2048) 처리량 + bf16 corr 상대오차/NN 일치. (실측: 20~123×, 오차<0.25%).
- **exact kNN/유사도**: vs **FAISS IndexFlatIP/L2**(최적 SGEMM+블로킹, 공정 baseline) + numpy — 동일 임베딩서 시간 + **recall@k**(실측 numpy 대비 75~115×, recall@10 0.99; FAISS 대비는 다음).
- **kernel(NTK/GP)**: vs BLAS Gram — 백만-스케일 feasibility + 정확도.
- **공통 게이트**: 각 도메인 정확도 지표(MP거리/corr오차/recall) 통과하며 SOTA 대비 net-win. **AMX-엔진 격리**=동일정밀 AVX-512 대비 천장(~10×), bf16-vs-fp32 conflate 정직 명시.
- **통합 그림**: K-sweep phase(AMX vs BLAS), 도메인별 speedup·정확도 표.

## 5. 이미 확보 / 남은 작업
- **확보**: MP(STUMPY 2.6~100×·정확도 동일), correlation(BLAS 20~123×·오차<0.25%), kNN(recall@10 0.99·75~115× vs numpy), 천장(10.2×), 멀티코어(32 TFLOP/s). (`newidea/microbench/`).
- **남은**: (a) **FAISS 공정 baseline**(kNN, 핵심 — numpy는 naive), (b) NTK/GP 백만-스케일 데모, (c) INT8, (d) 각 도메인 실데이터(UCR·유전체·임베딩), (e) 통합 라이브러리 API.

## 6. 리스크
- **분산 위험**: 폭이 넓어 "각 도메인 baseline이 얕다"는 비판 → **각 primitive마다 진짜 SOTA(STUMPY·FAISS) 대비 필수**. (얕으면 TSK_055로 후퇴.)
- **bf16 conflate**: "AMX냐 bf16이냐" → 천장(동일정밀 AVX-512 10.2×)으로 엔진 격리, 정직 명시.
- **ANN 경계**: sublinear SOTA(HNSW) 영역은 우리 것 아님 — exact/all-pairs로 범위 한정.
