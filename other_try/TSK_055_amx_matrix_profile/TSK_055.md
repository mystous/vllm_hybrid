# TSK_055 — "AMX Matrix Profile": in-DBMS 시계열 motif/discord 연산자 (좁고 확실)

*생성 2026-06-18. 타깃: SIGMOD / VLDB / ICDE (DB 시스템). 가장 단단한 프레이밍. 근거 실측 = `/home/mystous/newidea/`.*

## 0. 한 줄 요약
**Intel AMX(행렬 타일 엔진)로 matrix profile을 brute-force GEMM(`QT=S·Sᵀ`)으로 계산해, 공식 SOTA 라이브러리
STUMPY(STOMP)를 단일 노드 CPU에서 2.6~100× 능가**한다. 핵심 = (1) all-pairs를 GEMM으로 재정식화 → 행렬엔진 활용,
(2) z-정규화 cancellation을 막는 **사전정규화** 수치 설계, (3) fused·blocked 커널로 메모리-bound 회피. GPU 불요.

## 1. 아이디어 (왜 신규)
- Matrix Profile(MP): 길이 n 시계열의 모든 길이-m 서브시퀀스 쌍의 z-정규화 거리 중 최근접을 구함 → motif(반복)·discord(이상) 탐지. 시계열 데이터마이닝 표준.
- **기존 모두 O(n²) recurrence(STOMP) 또는 FFT(STAMP)** — QT(슬라이딩 내적)를 점화식으로 O(1)/cell 갱신, **거리 행렬을 절대 materialize 안 함, 행렬엔진(SIMD/텐서/AMX) 미사용.**
- **우리 통찰**: MP의 핵심은 `QT[i,j]=Σ_k S[i+k]S[j+k]` = 모든-쌍 내적 = **GEMM `S·Sᵀ`**. brute-force는 O(n²m)으로 m배 많은 FLOP이지만, **AMX 행렬엔진이 그 m배를 압도하는 처리량**(단일코어 bf16 3.35 TFLOPS, AVX-512 대비 10.2×)으로 역전.
- **신규성 검증**: "AMX + matrix profile" 동료심사 선행 **0편**(WebSearch 5그룹 교차확인). MP 가속은 전부 GPU(SCAMP)·SIMD·PIM이지 CPU 행렬엔진(AMX) 아님.

## 2. 분야 SOTA (정확히)
| 기법 | 핵심 | 복잡도 | 행렬엔진 | 비고 |
|---|---|---|---|---|
| STAMP (2016) | MASS/FFT로 거리 프로파일 | O(n² log n) | ✗ | FFT 기반 |
| **STOMP (2016)** | QT 점화식 O(1)/cell | **O(n²)** | ✗ | CPU 표준 |
| SCRIMP++ (2018) | anytime/순서 | O(n²) | ✗ | |
| **SCAMP (2019)** | STOMP+GPU/분산, FP64/centered | O(n²) | GPU(FP) | 대규모 SOTA |
| **STUMPY (2019~)** | numba STOMP, multi-thread/dist/GPU | O(n²) | ✗(CPU) | **공식 라이브러리·비교 baseline** |
- **우리 baseline = STUMPY**(사람들이 실제 쓰는 것) + SCAMP(가능 시). 둘 다 행렬엔진 미사용 → AMX-GEMM이 직교적 새 축.

## 3. 우리 방식 (알고리즘)
1. **GEMM 재정식화**: 서브시퀀스 행렬 S(L×m, L=n−m+1) → `QT = S·Sᵀ`(L×L). z-정규화 거리 d²(i,j)=2m(1−corr), corr=(QT−m μᵢμⱼ)/(m σᵢσⱼ).
2. **★ 사전정규화(핵심 수치 기여)**: 위 식은 `QT − m μᵢμⱼ` = 큰 수의 차 → **catastrophic cancellation** → naive bf16 motif **9.2%로 붕괴**(실측). **GEMM 전에 각 서브시퀀스를 z-정규화**하면 `QT=corr×m`이 되어 cancellation 제거 → bf16 motif **99.6% 회복**. (저정밀 MP의 필수 설계 원칙.)
3. **AMX bf16 GEMM**: `_tile_dpbf16ps`(16×K bf16 × VNNI-packed → 16×16 fp32 누적). B(=S) VNNI 사전패킹.
4. **fused tile→reduce**: 거리행렬 미materialize(O(L) 메모리) — 타일 계산 즉시 행별 min(exclusion zone) 갱신.
5. **B-panel L2 블로킹**: nb를 L2-맞춤 패널로 → B DRAM 트래픽↓ → 대형 n서 memory-bound 회피(코너 0.5×→2.6× 전환 실측).
6. **OpenMP 멀티코어** + (옵션) INT8 변형(per-window 스케일링, 천장 10×).

## 4. 검증 방법 (실험 설계)
- **Baselines**: (a) **STUMPY**(공식, numba STOMP, 동일 스레드), (b) SCAMP-CPU(가능 시), (c) fp32-BLAS brute-force(OpenBLAS, AMX 기여 격리용), (d) hand-tuned AVX-512(동일정밀 엔진 격리).
- **Datasets**: 합성 랜덤워크(스케일 sweep) + **UCR Time Series Archive**(motif 뚜렷, 인덱스 정확도 검증) + 실제(ECG/지진/IoT 텔레메트리).
- **Metrics**: (1) 처리량/지연(e2e + GEMM 분리), GFLOP/s. (2) **정확도 게이트**: MP 거리 상대오차, motif/discord 인덱스 일치, near-tie 분리(거리오차 vs 인덱스).
- **Ablations**: 사전정규화 on/off(9.2%→99.6%), fused vs materialize, blocking NBP sweep, bf16 vs int8 vs fp32, 멀티코어 스케일.
- **(n,m) phase diagram**(핵심 그림): m∈{128…1024}×n sweep → AMX 우세/STOMP 전환 경계.
- **게이트(논문 주장 성립 조건)**: 정확도(motif 동일·MP거리<1%) 유지하며 STUMPY 대비 ≥2× 전 영역(실측 2.6~100×).
