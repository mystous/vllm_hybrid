## 병목 분석 (H3 기각의 기전 — 사전등록된 대체 서사)

1. **t0-마스킹**: eager 모드에서 GPU arm 의 스텝 바닥시간 t0 이 지배적 (graphs 대비 9.5×) → GPU 의 "검증 낭비 비용" (β·M·(K+1)) 이 t0 에 묻힘 → **양팔 모두 '낭비 공짜' 상태가 되어 비용 구조가 동일해짐** → K* 가 같은 위치 (accept-length 포화 ~3.3 + draft 직렬 지연이 공통 제약) 에서 결정
2. 이론 재해석: 이는 H2 ("낭비 공짜") 자체와 **모순되지 않음** — 오히려 "낭비가 공짜인 두 시스템은 같은 K* 를 가진다" 는 이론의 자연스러운 따름정리. H3 의 검정에는 **GPU 낭비 비용이 노출되는 조건** 이 필요
3. **검정력 복원 경로 (E3b)**: t0/M 은 M 로 상각되지만 검증 낭비 β(K+1)/gen 은 M-무관 → **M=128** 에서 GPU arm 은 낭비-비용-지배로 전환, hybrid 는 expert 포화 (T=128·(K+1)) 로 여전히 공짜 → 이론상 gap 재출현. E0 도 M↑ 에서 gap 확대 예측 (M=64: +5~+11)

## E3b 판정

- **H3: M=128 에서도 기각** — 양팔 K*=3. eager t0/M 상각으로 GPU 낭비항이 노출될 것이라는 복원 가설은 실측 미지지 (eager t0 가 M=128 에서도 지배적)
- **이론-정합 세부 발견 (curvature 역전)**: 정점 후 하강이 M=32 에선 hyb 가 완만 (K3→K5: −2.6% vs −6.8%), **M=128 에선 hyb 가 가파름** (K3→K10: −31.6% vs −24.7%). 원인 = M=128·K10 에서 T=1,408 → n_e ≈ 88 ≈ **E1 실측 knee (75~129) 도달** — hybrid 의 "낭비 공짜 구간" 이 compute roofline 에서 끝남을 시스템 수준에서 재확인. **E1 microbench → E3b 시스템 거동의 정량 연결 고리** (논문 가치)
- E2 (스텝시간): K0→K3 스텝시간 배율 1.91× (hyb, 토큰 4× 대비) — 검증부는 sublinear 하나 draft 직렬 지연 포함 시 H2 게이트 (≤0.15 기울기) 는 시스템 수준 미달. microbench 수준 (E1) 은 성립 — **"낭비 공짜" 는 expert 연산에 국한, draft chain 은 공짜 아님** 으로 정밀화

## 종합 (E3+E3b)

1. H1 ✅ / H2 부분 (expert 한정) / **H3 ✗ (eager 체제, M∈{32,128})** / H4 상당 (spec 결합 1.45~1.55× 실측) / H6 미검 (α 분리 실패)
