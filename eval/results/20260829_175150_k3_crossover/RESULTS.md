# K3 — 복제(D) vs 통합(S) 부하-정합 교차점 + 전환 비용 (Footprint-Elastic 후보 kill-test K3)

- 목적: "부하에 따라 S(전체 머신 1-인스턴스)와 D(4+4 분할 2-인스턴스)를 동적 전환하는 컨트롤러"가 성립하려면 **교차점이 존재**해야 한다 — 그 존재 여부를 부하-정합 비교로 판정
- 구성: Qwen3-Coder-480B-A35B-FP8 + kt AMXINT4. S = TP4 + cpuinfer 96 (threadpool 2, 전체 머신). D = (GPU0-3+소켓0, cpuinfer 48) + (GPU4-7+소켓1, cpuinfer 48), cgroup cpuset 격리. 부하: sonnet 512/128, seed 42, 동시성 C sweep. turbo OFF (2.0GHz) 하한값.
- 주의: S 는 TP=8 이 불가(FP8 block 제약, TSK_047 r2)하므로 GPU 4장 + 전체 CPU 구성이다. D 와 GPU 수가 다른 것이 아니라, D 는 나머지 4장으로 **동일 모델 인스턴스를 하나 더** 띄운 것.

## 부하-정합 곡선 (총부하 = 총 동시 요청 수)

|---:|---:|---:|---|
| 1~2 | 4.55 (212) | 4.4/instance (216) | 동률 (단일요청 지연 동일) |

- 전환 비용 (콜드 재부팅): S→D **83초**, D→S **86초** (가중치 232GB 는 page cache 에 상주하므로 재부팅이 빠름)
- 참고: 전날 D 합산 61.2 (C=16each) 는 세션 조건이 달랐던 값 — 본 세션 동일조건 재측정 68.9 로 갱신. "+37%" 표기는 부하 불일치 비교였음 (사용자 지적) → 부하-정합 시 D 우위는 +2~12% 수준이 정확한 값.

## 판정

**교차점 없음 — 측정 전 구간 (1~64) 에서 D ≥ S, TPOT 도 D 가 근소 우위.** 격차는 부하 증가에 따라 축소 (+12% → +2%) 하나 역전은 없다.

따라서:
1. **K3 게이트 FAIL** — "부하별 승자가 갈려야" 동적 전환 컨트롤러가 성립하는데, 승자가 항상 D 다. 컨트롤러는 지을 이유가 없다 (그냥 항상 분할).
2. **K4 (diurnal 시뮬) 는 무의미 (moot)** — 전환 이득의 원천인 교차가 없으므로 실행하지 않음.
3. 원인 해석: CPU expert 연산은 스레드 확장이 준선형 (메모리 대역폭 한계) + kt threadpool 2 의 cross-NUMA 비효율 → 소켓 경계로 쪼갠 NUMA-로컬 풀 2개가 항상 더 효율적. GPU 쪽도 TP4×2 가 TP4×1 보다 collective 부담이 늘지 않는다.

## 운영 지침 (본 실험의 실질 산출물)

capacity-초과 MoE 를 kt-hybrid 로 서빙할 때, **머신을 소켓 경계로 쪼개 인스턴스를 늘리는 분할 구성이 전 부하 구간에서 통합 구성보다 낫다** (+2~12%, 지연도 손해 없음). 단일요청 지연이 요건이어도 D 가 S 와 동일 (212 vs 216ms) 하므로 통합 구성을 쓸 이유가 없다.
