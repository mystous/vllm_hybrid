## 3. 실패가 드러낸 기전 4개 (이 실험의 실질 산출)

1. **kt 는 hot expert 배치를 하지 않는다**: `--kt-num-gpu-experts x` = **id < x 고정** (코드 확인: `mask_cpu_expert_ids`, id 트래픽 share 실측 10.0%/21.3% vs hot-16/32 60/79%). 빈도 기반 배치는 미구현 기능 = 정량화된 개선 기회.
2. **expert 연산은 overlap 되어 있고, 고스레드에서는 비-expert 바닥이 binding**: x-sweep 이 TPOT 을 전혀 안 움직임 (287~288ms 고정) vs 스레드 sweep 은 크게 움직임 (668→417→288). 구조는 합(t_cpu+t_gpu) 이 아니라 **max(CPU, 바닥)** — 96thr 에서 바닥 ~288ms (62층 × ~4.6ms: launch+TP4 allreduce+kt 왕복).
3. **소형 모델은 layer 고정비가 전부 지배**: 30B TP1 은 C=1~64 에서 TPOT 131~137ms 고정 (48층 × ~2.7ms) — expert 비용과 무관.
4. **쿼터-소켓 분할은 소켓 내 대역폭 공유로 손해**: quad C8each 실측 506ms vs 법칙 396ms — 같은 소켓의 2개 인스턴스가 로컬 195GB/s 를 나눠 씀 (법칙은 136GB/s 독점 가정).

## 4. 부산물 (능력 기록)

- **480B ← GPU 2장 + CPU 서빙 성립** (TP=2, FP8 제약 1280/128 ✓)
- **머신 1대 = 480B × 4 인스턴스 동시 서빙** (부팅 224초, 인스턴스간 간섭 ≈0, 완전 대칭)
- **분할 최적점 존재**: 총부하 32 에서 dual(68.9) > quad(63.3) > ... — K3 의 "분할 우위" 는 2-분할에서 정점 (layer 바닥 + 소켓 공유가 4-분할을 벌함)

## 5. 최적성 gap (헤드라인 지표의 최종 수치)

라우팅-인지 하한 (실측 U=51.1, 양소켓 로컬 390GB/s): 83.4 tok/s @C16. 실측 최고 55.5 → **시스템은 하한의 67%**. 나머지 33%p 는 기전 ②의 비-expert 바닥이 소모 — "스케줄링 개선이 아니라 launch/동기화 오버헤드 제거가 헤드룸의 본체"라는 분해가 가능해짐. (단, 이 수치의 논문화는 후보 기각으로 보류)
