## EXP-E05 — E(메모리·동시성 설계) × R(실행 패치) 기여 분리

R0 = 성능 패치 해제(정확성 수정·τ deferral 유지), R1 = 최종 패치 묶음(callback-free, expert별 AMX 선택, AVX 레지스터 블로킹·prefetch, gather·양자화 융합).

| E_old (bf16, graph 96) | 716.86 | 805.27 | **+12.3%** |
| E_epoch (FP8, graph 224) | 710.39 | 792.18 | **+11.5%** |

**각 셀의 최적 C**

| | R0 | R1 | R 효과 |
|---|---|---|---|
| E_old (C96) | 754.80 | 883.52 | +17.1% |
| E_epoch (C224) | 926.93 | 1052.17 | +13.5% |

상호작용 `I_ER` = (F11−F01) − (F10−F00) = **−3.5 tok/s**(최적 C), **−6.6 tok/s**(C64) 로 사실상 0. 두 성분은 독립이며 **고정 동시성에서는 R 만 +12% 를 만들고 E 는 −1% 비용**, E 의 가치는 최적 운영점을 C96 → C224 로 여는 데 있다.

## EXP-E04 — CPU 연산 자원 민감도 (문서 §10.2)

`--kt-cpuinfer` 48 / 72 / 96, E_epoch + R1.

| CPU 워커 | C64 tok/s | C224 tok/s |
|---|---|---|
| 48 | 667.08 (−15.8%) | 844.67 (−19.7%) |
| 72 | 748.97 (−5.5%) | 972.34 (−7.6%) |
| 96 | 792.18 | 1052.17 |

- 워커 2배(48→96)에 처리량 C64 +18.8%(스케일링 지수 0.25), C224 +24.6%(지수 0.32).
- **CPU 는 임계 경로의 실제 연산 주체**다(저장 장치가 아님). 동시에 **이미 수확 체감 구간**이며, 이는 "CPU 시간의 88%가 가중치 스트리밍, 대역폭이 실용 상한"이라는 E03 결과와 일치한다. 코어 증설보다 바이트당 유효 행 증가가 유효하다는 EPOCH 논리를 뒷받침한다.
- 동시성이 높을수록 CPU 민감도가 커진다(0.25 → 0.32).

## EXP-E08 — mixed forward 의 고정 C 대조 (문서 §14.4)

| C | 처리량 off → on | TTFT p50 off → on | TPOT p99 off → on |
|---|---|---|---|
| 64 | 792.18 → 785.29 (**−0.9%**) | 2.51 s → **1.52 s (−39%)** | 75.80 → 74.83 |
| 160 | 976.73 → 969.51 (**−0.7%**) | 4.96 s → **1.66 s (−67%)** | 150.43 → 148.11 |
| 224 | 1052.17 → 1046.45 (**−0.5%**) | 6.15 s → **2.19 s (−64%)** | 194.09 → 187.92 |

- 같은 동시성에서 mixed 의 대가는 **처리량 −0.5~0.9%** 뿐이고 TTFT 는 39~67% 개선, TPOT p99 는 동등하거나 소폭 개선.
- 이전 기록의 "mixed 처리량 −7%"는 λ 가 다른 운영점 비교였다. **동일 C 기준 정확한 대가는 −0.5~0.9%** 로 정정한다.
- 문서 §14 가 우려한 TPOT·최대 처리량 악화는 버스트에서 관측되지 않았다. 단 물리 byte·operator 수준 대조(M0~M3)는 미수행이므로 "중복 읽기 감소"의 직접 증거로는 쓰지 않는다.

## EXP-E10 — 워크로드 일반화 (문서 §16)

| 워크로드 | C | EPOCH-B | TUNED | 차이 |
|---|---|---|---|---|
| W0 512/128 | 64 | 792.18 | 805.27 | −1.6% |
| W0 512/128 | 각자 최적 (224 / 96) | **1052.17** | 883.52 | **+19.1%** |
| W3 4096/128 | 32 | 142.92 | 132.29 | +8.0% |
| W3 4096/128 | 64 | 150.11 | 135.06 | **+11.1%** |
| W4 512/1024 | 64 | 438.41 | 557.47 | **−21.4%** |
| W4 512/1024 | 각자 최적 (160 / 96) | **659.90** | 585.46 | **+12.7%** |

- **동시성 확대 이득은 요청당 KV 요구에 반비례**한다: W0 에서 C64→C224 +33%, W4 에서 C64→C160 +50%, **W3(긴 입력)에서는 C32→C64 +5% 로 사실상 없음**(기준선은 오히려 +2%에 그치고 TTFT p50 48초).
- **W4 고정 C64 에서 EPOCH 이 −21.4%** 로 크게 뒤진다. 출력이 길어져 문맥이 계속 자라면 FP8 KV 의 역양자화 비용이 매 토큰 전 문맥에 누적되기 때문으로 보인다(짧은 출력에서는 −1.6%). 이 영역은 각자 최적 C 로 가야 EPOCH 이 +12.7% 로 역전한다.
- sonnet 512/128 전용 튜닝은 아니다. 다만 **이득의 크기와 필요한 운영점이 워크로드마다 다르므로, 고정 C 로 배포하면 손해를 볼 수 있다**(W4 C64 −21%). 구성 선택이 필요하다는 EXP-E11 의 동기.
