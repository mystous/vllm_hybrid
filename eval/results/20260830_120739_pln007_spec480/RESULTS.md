## 성립의 전제가 된 수리 3건 (전부 이번에 발견)

1. SGLang `qwen3_moe.forward_normal` 이 expert 배치 정보를 라우터에 안 넘김 → 재배열 시 조용한 붕괴 (1줄 패치)
2. kt 는 추론 모드에서 `num_gpu_experts` 숫자를 무시하고 `gpu_experts_mask` 목록만 봄 — 기존 호환 패치가 목록을 None 으로 고정해 **CPU 전량 계산 + GPU 중복 덧셈** 상태였음 (mask 생성 패치)
3. hot-expert 선정: kt 는 id 순 고정 → EPLB 맵 주입 (`--init-expert-location` + P0a 빈도) 으로 가중치 파일 수정 없이 해결

## 품질 판정 — 미완 (진행 중)

- 표면 문항 (greedy 4종): 통과
- 같은 토큰열 분포 비교 (base INT4-전량 vs 개선): meanΔlogprob 0.106 / **maxΔ 3.29 / PPL 상대차 최대 16.9%** — 분포가 실제로 다름
- 해석: hot 32개 (트래픽 60%) 가 INT4→FP8 로 계산 정밀도가 바뀐 구조적 결과
- **최종 판정 (GSM8K 40문항, chat 형식, greedy)**: base 85.0% (34/40) vs 개선 **92.5% (37/40)** — 저하 없음 (수치상 상회, 표본 40이라 상회 자체는 확정 주장 안 함). 분포 변화는 정밀도 향상 방향으로 해석됨. **품질 게이트 통과 → 성능 수치 유효 확정**
