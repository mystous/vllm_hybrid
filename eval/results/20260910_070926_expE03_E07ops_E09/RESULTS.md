## EXP-E07 확장 — 양쪽에 동일하게 mixed forward 적용 (문서 §2.2 동등 탐색 기회)

| λ (req/s) | TUNED+mixed 완료율 / tok/s / TTFT p99 / TPOT p99 | EPOCH-OPS 완료율 / tok/s / TTFT p99 / TPOT p99 |

| 5 | 3.58 / 457.9 / **17.05 s** / 253.7 ms | 4.13 / 527.8 / **0.98 s** / 211.6 ms |
| 7 | 3.62 / 463.4 / 44.55 s / 253.1 ms | 5.16 / 659.9 / **2.31 s** / 282.9 ms |

| 11 | — | 5.74 / 734.0 / 16.75 s / 294.5 ms |

- **포화 완료율**: 기준선 **3.6 req/s** (λ 5/7/9 에서 3.58/3.62/3.59 로 고정), EPOCH-OPS **5.74 req/s** → **+59%**.
- **사전 고정 SLO (10 s / 300 ms) 최대 지속 λ**: 기준선 **3** (그때 365.5 tok/s), EPOCH-OPS **7** (659.9 tok/s) → **도착률 2.3배, 출력 처리량 +80%**.
- (5 s / 200 ms): 기준선 λ=3 통과, EPOCH-OPS 는 λ=3 에서 TPOT p99 156.8 ms 로 통과 → **양쪽 λ=3 동률**. (2 s / 100 ms): 양쪽 모두 불가.
- mixed 이득은 EPOCH 고유가 아니다. 기준선도 TPOT p99 171 → 121 ms 로 개선된다. **차이는 KV 여유가 대기열을 흡수하는 λ≥5 영역에서만 발생**한다.

### 앞선 판정의 수정
mixed 를 끈 구성만으로 낸 "어떤 SLO 에서도 EPOCH 우위 없음"(`*_expE06_E07/RESULTS.md`)은 **운영 옵션을 뺀 구성에 한정**된 결론이다. 문서 §2.2 대로 양쪽에 동일 옵션을 준 비교에서는 (10 s/300 ms) 조건에서 EPOCH 가 우세하다. 두 결과를 모두 보존한다.

## EXP-E03 — CPU 연산 효율·가중치 스트리밍 기전 (문서 §9)

**물리 DRAM 카운터 측정 불가**: 컨테이너에 `perf` 미설치(`perf_probe.txt`: command not found). 문서 §9.4 규정에 따라 아래 지표는 `expert_dram_bytes` 가 아니라 **서버 내부 계측 기반 상대 지표**로 명명한다.

서버 위상 프로파일러(`KT_PHASE_PROF=1`) 1,691개 표본, 소켓 0 기준 중앙값:

| 구성 | 실제 배치 qlen | 활성 cold expert | 한 expert 최대 행 | 층당 CPU | 활성expert/qlen | 상대 bytes/유효행 |
|---|---|---|---|---|---|---|
| TUNED (최적점) | 96 | 10 | 4 | 745 µs | 0.1042 | 100% |
| EPOCH-B | 64 | 8 | 2 | 567 µs | 0.1250 | **120%** |
| **EPOCH-B** | **224** | 16 | 7 | 1269 µs | 0.0714 | **68.6%** |

- 비율에서 cold 라우팅 비율과 expert 바이트가 약분되므로 **가정 없는 상대 지표**다.
- 동시성 64 → 224 에서 배치 토큰은 3.5배 늘지만 스트리밍할 cold expert 는 2배만 늘어, **가중치 읽기 바이트당 유효 행이 1.75배**(bytes/유효행 −42.9%).
- 기준선이 도달 가능한 최대 동시성(C96) 대비로도 **−31.4%** 로, 문서 §9 판정 목표(10% 이상 감소)를 충족한다.
- 낮은 동시성(C64)에서는 기준선보다 20% **나쁘다**. E06 에서 C32~C96 구간 EPOCH-B 가 느렸던 이유가 이것이다.
- 계측 오버헤드(문서 §3.5): C224 1104.6 vs 계측 없음 1109.6 = **0.5%**, C64 774.7 vs 792.2 = 2.2%.
