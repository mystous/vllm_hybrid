# EXP-E00 / E01 / E02 — EPOCH 실행계획서(af864ae9) 묶음 A+B 1차 실행

문서: `shadow_assists/brainstorming/epoch_experiment_plan_20260909.md` §5~8. ID: `IDE_058`.
공통 고정(문서 §2.1): hot-96 α=0.25 map, common R (callback-free, τ=0.25 Dτ, expert별 AMX 선택, AVX 레지스터 블로킹·prefetch, gather·양자화 융합), chunk 4096, mixed off, mem-fraction 0.94, TP=4.
워크로드: sonnet 512/128 prefix 100, 프롬프트 3×C, seed 42. **모든 측정 전 `/flush_cache` (HTTP 200 확인) 후 3초 대기.**

## EXP-E00 — 구성·측정 정의 고정에서 나온 사실

| 확인 항목 | 결과 |
|---|---|
| 과거 KV 37,487 의 정체 | KV dtype 이 아니라 **mem 0.92 + `--max-total-tokens 49152` 상한**의 결과. 같은 mem 0.94·상한 없음에서 bf16 은 **63,654 토큰** |
| FP8 의 순수 용량 효과 | 동일 mem·동일 graph 에서 bf16 63,654 → FP8 **127,309 토큰 (정확히 2.0배)**, GPU 사용량은 78.6 GB 로 동일 |
| graph 버킷 축소의 메모리 효과 | graph max 64 에서 dense→sparse 는 KV 63,654 로 **변화 없음** (GPU 메모리 78.6 → 78.5 GB). IDE_049 의 KV 확대는 **큰 배치 버킷(max 192/224)** 을 줄일 때만 발생 |
| 캐시 오염 | 같은 서버에서 C32(96 프롬프트) 뒤 C64(192 프롬프트, 앞 96개 동일)를 재면 **+20.4% 부풀려짐** (971.75 → flush 후 807.15). 이후 모든 셀은 flush 적용 |
| C_client vs B_decode | C224 에서 실제 decode 배치는 **중앙값 160 / 최대 224**. C_client 를 배치 크기로 해석하면 안 됨 |

## 44% 의 분해 (같은 노드, 같은 날, flush 적용)

| 단계 | 값 | 델타 |
|---|---|---|
| 과거 기록 C64 (HIST-769) | 769 | 기준 |
| REF-COMMON C64 = 실행 패치 R + KV 풀 복원 (bf16, 상한 없음) | **807.2** | +5.0% |
| 최종 B 구성 C64 (E 추가, 동일 동시성) | 779.3 | **−3.5%** |
| 최종 B 구성 C224 (용량을 동시성으로 전환) | **1109.6** | **+42.4%** |

문서 §8.5 의 지시대로 단순 퍼센트 합으로 분해하지 않는다. 확인된 것은 (1) E 성분은 고정 동시성에서 음(−)의 실행 효과를 갖고 (2) 전체 이득은 동시성 확대 경로에서만 나오며 (3) 그 경로는 KV 용량과 admission 두 지점에서 각각 차단하면 사라진다는 것이다.
