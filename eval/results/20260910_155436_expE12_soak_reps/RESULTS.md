## 3. EPOCH-OPS 사망 — 수치 실패 (→ IDE_063)

λ=5.0 을 2분간 처리하다 (실행중 요청 97, 토큰 사용률 0.38) 샘플러에서 device-side assert:

```
Assertion `probability tensor contains either `inf`, `nan` or element < 0` failed.
torch.AcceleratorError: CUDA error: device-side assert triggered
  ... ForwardBatch.init_new -> clamp_position(batch.seq_lens)
```

TP 4랭크 전부 예외로 종료. 같은 세션에서 TUNOPS·EPCORE 는 동일 assert 0건.
다만 IDE_058/E07-ops 에서 같은 (fp8_e5m2 + mixed) 구성이 λ 3~11 을 통과했으므로 결정론적이지 않다.
원인 분리는 `IDE_063` 에서 4셀 (fp8+mixed / 지연 expert 끔 / bf16+mixed / mixed 끔) 로 진행한다.

**주의**: 이 구성이 IDE_058 에서 "동일 SLO 도착률 2.3배" 를 낸 구성이다. 원인이 밝혀지고 수리되기 전까지
EPOCH-OPS 의 지속 운전 가능성은 확인되지 않은 것으로 취급한다.

## 4. 물리 DRAM (perf uncore_imc, 소켓별 8채널)

이번 세션에서 `perf` 를 설치해 §9.4 의 미달 항목을 채웠다. 정상상태 창만 사용 (짧은 run 은 지속시간의 25%, 긴 run 은 60초 램프 배제).

| 구간 | 실행중 요청 | 출력 tok/s | S0 읽기 | S1 읽기 | 읽기 합 | 쓰기 합 | **출력 토큰당 읽기** |
|---|---|---|---|---|---|---|---|
| EPCORE 저부하 | ~23 | 189.77 | 127.5 | 127.4 | 254.9 | 10.2 | **1,343 MB** |
| EPCORE 저부하 복귀 | ~23 | 189.78 | 127.1 | 127.0 | 254.1 | 10.2 | **1,339 MB** |
| EPOPS 저부하 | ~24 | 189.70 | 128.8 | 128.7 | 257.6 | 10.5 | **1,358 MB** |
| EPCORE 용량근접 | ~100 | 565.22 | 73.7 | 72.0 | 145.7 | 22.7 | 258 MB |
| EPCORE 반복 C224 | 224 | 1,039~1,058 | 108.9~112.3 | 104.3~108.9 | 213~221 | 44~51 | **202~213 MB** |
| EPOPS 반복 C224 | 224 | 1,029~1,031 | 108.9~113.5 | 106.0~111.2 | 215~225 | 48~55 | 209~218 MB |

관측:

1. **메모리 트래픽 총량은 부하와 거의 무관하다.** 저부하(실행중 23)에서 255 GB/s, 고부하(224)에서 217 GB/s
   로 오히려 저부하가 높다. CPU expert 의 가중치 읽기가 스텝·층 단위 고정비이기 때문이다.
2. **토큰당 읽기는 6.4배 차이** (1,343 → 209 MB). 처리량 이득의 인과가 물리 카운터로 확인된다:
   FP8 KV → KV 풀 2배 → 동시성 확대 → 이미 지불 중인 가중치 읽기가 더 많은 토큰에 분산.
   EXP-E03 에서 논리 대리지표로 보고한 "유효 행당 바이트 −31.4%" 의 물리적 근거.
3. 쓰기는 배치에 비례한다 (10 → 47 GB/s). KV 쓰기.
4. mixed forward 는 DRAM 바이트를 바꾸지 않는다 (저부하 1,343 대 1,358 MB, 1.1% 차이).
5. 반복 측정의 재현성: 같은 조건 저부하 두 구간이 1,343 대 1,339 MB (0.3%).
6. **소켓당 읽기 109~136 GB/s 는 이론 천장 282 GB/s 의 39~48%.** 서빙 중 메모리 대역폭이 절반 이상 남아 있다
   → `IDE_061` (hot expert 수 H 재탐색) 의 근거.

## 5. 저부하 토큰 지연 이상 (→ IDE_062)

저부하(λ1.5)에서 세 구성의 처리량은 모두 190 tok/s 로 같지만 TPOT 는 기준선 62.0 ms,
EPOCH-CORE 123.3 ms, EPOCH-OPS 108.3 ms 다. mixed forward 를 끈 조건 (IDE_062 D0) 도 107.30 ms 로 같아 mixed 는 원인이 아니다.
**IDE_062 에서 원인이 특정됐다: fp8_e5m2 KV dtype 단독이다.** 다른 축 (KV 풀 크기, graph 구성,
mixed forward) 을 모두 고정하고 dtype 만 bf16 으로 바꾸면 TPOT 가 107 -> 66.5 ms 로 38% 내려가
기준선과 일치한다. 이 비용은 배치 13~21 에서 +61%, 배치 64 에서 +1.7% 로 소배치에서만 드러난다.
