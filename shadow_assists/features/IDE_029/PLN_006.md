# PLN_006 — PlacementBound 실험 플랜: "어떻게 실험하는가"

> 부모: `IDE_029`. 후보 정의·초록·kill-test 사전등록: `brainstorming/problem_search_20260829.md` §8
> 목표: "MoE expert 를 어디에 두고 어디서 계산할지"의 **데이터 이동 하한 모델**을 만들고, 그 모델이 실측을 **사전 예측**함을 보인다.

## 0. 방법론 원칙 — 순환 적합 금지 (이 플랜의 생명선)

1. **모델 파라미터는 스펙시트와 마이크로벤치에서만 얻는다.** end-to-end 서빙 수치로 캘리브레이션하는 순간 이 논문은 죽는다 (예측이 아니라 곡선 맞추기가 됨).
2. **사전등록**: 모든 예측은 측정 **전에** `predictions.json` 으로 작성하고 git 커밋해 해시를 고정한다. 측정 후 대조.
3. 모델 수정은 E1 실패 시 1회 허용하되, 수정된 모델의 검증은 **새 예측 대상으로만** 한다 (같은 데이터 재사용 금지).
4. 결과는 통과든 실패든 셀 단위로 `eval/results/*_pln006_*/` 에 전량 기록.

## 2. E0 — 모델 구축 + 재예측 [1일]

### E0a. 모델 입력 마이크로벤치 (서빙과 무관한 측정만)

| 입력 | 획득 방법 | 상태 |
|---|---|---|
| 소켓당 DRAM 대역폭 B_C | STREAM triad, numactl 소켓별 (컨테이너 내) | **신규 측정** |
| CPU AMX 처리율 F_C(M) — 배치 M 의존 곡선 | 기보유: E1 microbench (`eval/results/20260829_001433_pln004_e1_amx_microbench/`) | 보유 |
| PCIe H2D/D2H 대역폭 B_P | torch cuda 전송 벤치 | **신규 측정 (10분)** |
| HBM 대역폭 B_G, GPU 연산율 F_G | 스펙 (H100: 3.35TB/s, BF16 ~1PF/s sparsity 제외) | 스펙 |
| 모델 구조 (L, E, top-k, expert 바이트, 공유부 바이트) | config.json 에서 자동 추출 | 스크립트 |

### E0b. 계산기 구현 — `placement_bound.py`

- 입력: `model.json` + `hw.json`
- 핵심 수식 (쉬운 말로): 토큰 하나가 층마다 k개 expert 를 깨우면, 그 가중치 바이트는 **저장된 곳에서 최소 1번은 읽혀야** 한다. 배치 M 이면 expert 당 재사용으로 1/M 로 나눠진다. HBM 에 못 올린 가중치가 활성화되는 만큼은 (a) PCIe 로 나르거나 (b) DRAM 에서 CPU 가 그 자리에서 읽거나 — 둘 중 하나는 피할 수 없다. 따라서 **시간 하한 = max(채널별 이동 바이트 / 그 채널 대역폭, 연산량 / 연산율)**. Hong-Kung pebbling 의 "연산기 2곳" 버전.
- 하한 유도는 다중 프로세서 red-blue pebbling (SPAA'24, 2409.03898) 위에 구축 — 새 이론 주장 금지, 첫 실체화 + 검증이 우리 기여
- 출력: ① 토큰당 이동량 하한 (채널별) ② 배치 정책별 예상 처리량 ②' **정책별·실측별 최적성 gap(%)** — π ∈ {GPU-only, hybrid(x=GPU상주 expert 비율), FlexGen식 전송, n-분할 복제} ③ 정책 간 승패 경계 조건
- NUMA 항: n-분할 복제 시 B_C 는 소켓당 값으로, 통합 시 threadpool cross-NUMA 페널티 계수 (STREAM 원격 접근 실측치로)

### E0c. 재예측 (retrodiction) — 파라미터를 뽑지 않은 기측정치 재현

| 재현 대상 (전부 기측정) | 실측값 | 판정 기준 |
|---|---|---|
| 30B (HBM 에 들어감) hybrid 의 손해 폭 | ~15× | ±30% |
| 480B hybrid TP4+96스레드 | 44.5 tok/s | ±30% |
| 480B 분할 4+4 인스턴스당 | 30.6 tok/s | ±30% |
| AMX knee 위치 (expert 당 토큰) | 75–129 | 구간 겹침 |
| K3 곡선 (S vs D, 총부하 4/16/32/64) | D +2~12% | 부호 전 구간 일치 |
| kt+GPU-only 모델 동거 무간섭 (D1) | ≈0% | 정성 일치 |

**전부 통과해야 E1 진입** (하나라도 크게 어긋나면 모델 구조 결함 — 수식 재검토).
