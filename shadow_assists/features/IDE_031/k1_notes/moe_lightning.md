## 문제·결정 변수
- 대상: MoE (Mixtral 8x7B/8x22B, DBRX) 의 **offline 배치** 추론, GPU 메모리 < 모델 크기, 디스크 미고려. FlexGen 의 zig-zag 순회 승계.
- 정책 6-튜플 (§4.2, Table 1): "The generated policy will be a 6-tuple (N, μ, Ag, Fg, rw, rc)." — 배치 N, 마이크로배치 μ, attention 을 GPU 에서 할지 Ag, MoE FFN 을 GPU 에서 할지 Fg, **정적으로 GPU 에 둘 가중치 비율 rw, GPU 에 둘 KV 비율 rc**. "For our major setting, we always get Ag = 0 and Fg = 1."
- 스케줄: CGOPipe (CPU attention + paged weights 로 I/O 인터리브).

## 비용 모델 파라미터 출처와 검증
- HRM (Hierarchical Roofline Model): 층별 `T = max(comm_cpu_to_gpu, T_cpu, T_gpu)`, `T_x = max(comm_x, comp_x)`, `comm = bytes/b`, `comp = flops/p`.
- **파라미터 출처 = 이론 FLOPs·바이트 + 프로파일한 피크 대역폭/FLOPS** (엔드투엔드 피팅 없음): "all the evaluation results of MoE-Lightning follow policies generated by a performance model with theoretically calculated computation flops and bytes with profiled peak performance and memory bandwidth for the hardware." / "without the need for extensive data fitting (might take hours or days) as needed in FlexGen".
- **절대 예측 오차는 보고하지 않음**, 상대 순위 용도로 한정: "While there are discrepancies between the theoretical performance estimation and the kernel's real performance, such modeling can provide a reasonable estimation of the relative effectiveness of any two policies."
- 검증 방식: 모델이 고른 정책으로 실측 처리량 비교 (FlexGen 에 자기 정책 이식 시 1.77×, Table 5), 예측값 대 실측값 대조 그림·수치 없음.
- 최적화: MILP, "takes less than a minute" (B.2).

## expert·KV 경합 취급
- rw (가중치 GPU 비율) 와 rc (KV GPU 비율) 를 같은 탐색·같은 `comm_cpu_to_gpu` 항 (CPU→GPU 대역폭 b_cg) 아래 결정. 다만 "we exclude disk-related variables from the search space and add two binaries" — FlexGen 의 LP 를 MoE 로 옮긴 형태. **expert 단위 상주 (어느 expert 를 hot 으로) 는 아님**: 가중치를 페이지 단위로 매 층 스트리밍하며, 정적 상주는 비율 rw 로만 표현.
- 인용 (§1): "Fundamentally, these solutions fail to take into account that changes in the workload can lead to changes in the bottleneck resource."
- **호스트 DRAM 대역폭 항 있음** (b_c, CPU 메모리 대역폭) — CPU attention 의 memory roof. 단 expert 스트리밍은 PCIe (b_cg) 항이며 DRAM 읽기와의 간섭은 모델링하지 않음 (CPU 측 가중치 읽기가 DRAM 을 쓴다는 항 없음).
- 인용 (§6.2): "our CPU attention kernel is 3−4× faster than KV cache transfer, which is close to the ratio of CPU memory bandwidth and the CPU to GPU memory bandwidth." / "As the micro-batch size and context length increase, the CPU attention will eventually become the bottleneck, which calls for higher CPU memory bandwidth."
- 인용 (§C Future Work): "when CPU attention emerges as the bottleneck, the KV cache budget can be adjusted to better balance CPU and GPU computation" — KV 예산 조정을 **미래 과제**로 둠.

## 우리와의 delta
- 그들이 이미 한 것: MoE 서빙에서 (가중치 비율, KV 비율, 배치, 연산 위치) 를 스펙+피크벤치 파라미터의 roofline 모델로 결정; 전이점 (turning point) 형식화; 상대 순위 검증.
- 그들이 안 한 것: (a) **expert 단위 hot 집합 H** 와 라우팅 트레이스의 distinct-cold-expert 기대값 항 (그들은 가중치 전체를 매 층 페이지 스트리밍) — 우리 전이점의 x 축이 H 라는 점이 다름. (b) **DDR 예산**: expert 스트리밍이 PCIe 가 아니라 CPU 측 DDR 읽기 (kt CPU 커널) 이고 DRAM KV 읽기와 같은 DDR 을 나눔 — 그들은 PCIe 항 + CPU attention DRAM 항이 **분리**. (c) 절대 오차 (≤20%) 사전등록 없음 — "relative effectiveness" 만. (d) 온라인 서빙 (continuous batching, KV 가 GPU 에 상주하며 DRAM tier 는 선택) 이 아니라 offline zig-zag 배치.
- 우리가 못 주장하게 되는 것: "MoE 에서 turning point 를 처음 형식화" / "가중치와 KV 배치를 MoE 에서 처음 공동 결정" / "스펙-기반 모델로 정책 선택을 처음". 주장 1 은 "H 축 전이점 + DDR 예산" 으로, 주장 2 는 "절대 오차 사전등록" 으로 좁혀야 함. 위협도 **최상**.
