\section{방향: Host-Side Slack Reclamation}
\label{sec:direction}

특성화(\S\ref{sec:results})는 두 운영 함의를 낳는다:
(A) 모델-유형 인지 방법 선택으로 회귀를 피하고,
(B) spec-decode 가 만든 host 병목을 유휴 CPU 로 떠안는다.
본 절은 (B)를 중심으로 \algname\ (host-side slack reclamation) 설계 원칙을 제시한다.
본 절은 \emph{측정된 결과가 아니라 데이터에서 도출한 방향}이며,
이를 판정할 결정적 실험(\S\ref{subsec:decisive})을 함께 정의한다.

\subsection{설계 원칙: CPU는 GPU를 흉내내지 않는다}
\label{subsec:principle}

핵심 분류 기준은 단 하나다:
\emph{CPU 가 GPU 의 일(매트멀)을 대신하면 패배, GPU 가 내려놓은 host 작업을 받으면 승리.}
전자는 H2D/D2H 동기 비용과 CPU/GPU 연산 격차(1--2 orders)로 물리적으로 진다.
후자는 spec-decode 가 step 수를 줄이며 \emph{상대적으로 커진} host-path 작업을
이미 유휴인 CPU(\S\ref{subsec:res-resource}, $\le4.9\%$)로 이전한다.

Table~\ref{tbl:roadmap} 은 본 연구가 제안하는 개선 lever 를 한곳에 모은 로드맵으로,
각 lever 의 타깃 병목$\cdot$개선 논리$\cdot$기대 효과와 \textbf{현재 상태(TBD)}를 명시한다.
정량 결과는 \S\ref{subsec:decisive} 의 결정적 실험으로 지배 병목을 확정한 뒤 채운다.

\subsection{축 B — host-path 회수}
\label{subsec:reclaim}

성공 셀의 GPU 여유($1-u_{\mathrm{gpu}}^{\mathrm{suf}}$)와 유휴 CPU 를 결합해
드래프팅(A1)$\cdot$detok(B1)을
GPU verify 와 파이프라인한다. 목표는 GPU 이용률을 다시 끌어올려
줄어든 step 수에서도 GPU 를 채우는 것이다.
이종 모델 fleet 의 multi-tenant/long-context 에서는 유휴 DRAM 2TB 를 쓰는
KV tiering(A2)으로 배치를 키워 GPU gap 을 다른 요청으로 채운다.

\subsection{CPU 병렬성 reclamation 성능 모델}
\label{subsec:parallel-model}

reclamation 의 핵심 자원은 \emph{병렬성}이다.
suffix 가 step 수를 줄이면 step당 host-path 작업이 상대적으로 커지는데(\S\ref{subsec:problem-b}),
이 host-path 는 본질적으로 \emph{요청 단위로 분할 가능}하다(드래프트$\cdot$detok 는
요청마다 독립). 따라서 유휴 224 스레드에 병렬 분산하여 GPU verify 뒤로 숨길 수 있다.

한 decode step 의 GPU verify 지연을 $T_{\mathrm{verify}}$, 직렬 host-path 지연을 $T_{\mathrm{host}}$,
사용 가능한 병렬 CPU 코어 수를 $P$, 병렬 효율을 $\eta\!\le\!1$ 라 하면,
host-path 를 verify 뒤로 \emph{완전히 숨기는} 조건은
\begin{equation}
\frac{T_{\mathrm{host}}}{\eta\,P} \;\le\; T_{\mathrm{verify}}.
\label{eq:hide-condition}
\end{equation}
이 조건이 성립하면 GPU 이용률은 suffix 의 $u_{\mathrm{gpu}}^{\mathrm{suf}}$ 에서
다시 포화에 가깝게 회복되고, 처리량은 회복된 이용률에 비례하여 증가한다:
$T_{\mathrm{rcl}} / T_{\mathrm{suf}} \approx u_{\mathrm{gpu}}^{\mathrm{van}} / u_{\mathrm{gpu}}^{\mathrm{suf}}$
(상한). B200 의 $u_{\mathrm{gpu}}^{\mathrm{suf}}\!\approx\!26\text{--}65\%$ 와
$u_{\mathrm{gpu}}^{\mathrm{van}}\!\approx\!95\%$ 는 상당한 이론적 여유를 시사한다.

\smallskip
\noindent\textbf{[측정 기반 결과 — 본 baseline 부정].}
$\ge\!75$ host-path lever 의 직접 측정 (\S\ref{subsec:res-reclaim}, Table~\ref{tbl:reclamation},
Table~\ref{tbl:lever-summary}) 결과,
본 baseline 환경의 $T_{\mathrm{host}}$ 잔여항은 \emph{이미} B3-FaP $+$ L2-prefetch-tokenize $+$ L10-burst-admission
으로 흡수되어 측정 가능 noise band 이하다.
지배 항을 병렬화하려는 모든 시도 (env-flag, NUMA, AVX-512 helper, scheduler, host n-gram, Eagle3,
CPU sampling, 그리고 CPU AMX BF16 1B draft 까지 포함; \S\ref{subsec:res-amx-draft}) 가
0/$\ge75$ net-positive 다.
즉 본 baseline 에서는 식~\ref{eq:hide-condition} 의 좌변 자체가 정의되지 못한다
($T_{\mathrm{host}}\!\le\!\epsilon$).
적용 영역은 (a) host-bound regime, (b) hw-gap-smaller architecture (H100/A100/consumer GPU),
(c) long-context $\ge\!32$K multi-tier KV 로 재정의한다 (\S\ref{subsec:hw-gap-analysis}).

\subsection{결정적 실험}
\label{subsec:decisive}

축 B 의 타당성은 단일 측정으로 판정된다:
\emph{suffix ON 상태의 decode step 1개 wall-clock 을 GPU verify(커널 실행) 대
step간 gap(드래프트$\cdot$스케줄$\cdot$샘플$\cdot$detok$\cdot$동기)으로 분해}한다
(Nsight Systems inter-kernel gap + py-spy).
대상은 GPU 이용률이 가장 낮은 Qwen-2.5-7B suffix(26\%)와 대조군 Llama-3.1-70B suffix(83\%)다.
gap 이 크고 host-bound 이면(a) A1/B 가 회수 가능,
verify 내부 대역 bound 이면(b) CPU 로 불가 $\to$ A2(배치 확대)로 전환,
배치 미충전이면(c) concurrency$\uparrow$ + A2 가 1순위가 된다.
이 verdict 가 \algname\ 의 구현 우선순위를 확정한다(\S\ref{sec:discussion}).

\subsection{Lane-Separated Host Coprocessor (LHC): 시도와 기각}
\label{subsec:lhc-def}

식~(\ref{eq:hide-condition})의 좌변이 측정 가능 영역으로 들어가는 환경을
겨냥해, host 측을 자원 차원이 서로 다른 세 \emph{lane} --- DSA lane
(host memory bus; 8-WQ aggregate 56.88\,GB/s $=$ \texttt{cudaMemcpy} H2D
대비 1.046$\times$), AMX C3 lane (CPU vector ALU; prefix-cache 1\,MB
스캔 130\,$\mu$s), NEO swap lane (pinned DRAM $+$ PCIe) --- 으로 분리한
\textbf{Lane-Separated Host Coprocessor} (LHC) 와, 이를 PMU 신호로
조율하는 5-stage 오케스트레이터 \textbf{METRONOME-LHC}
(TEMPO/CHORD/METER/ACCENT/RITARDANDO; 구현 \texttt{vllm/v1/lhc/},
\texttt{VLLM\_LHC\_METRONOME=1} env gate, 비활성 시 전 hook no-op) 를
설계$\cdot$구현했다.

\emph{이 아이디어는 측정으로 기각되었다} (\S\ref{subsec:res-metronome-lhc}):
정적 활성은 본 baseline 에서 $-0.34\%$ noise band 에 머물렀고 ---
GPU-saturated regime 에서는 lane hook 자체가 호출되지 않는다 ---
계획했던 9 워크로드 $\times$ 7 config 통합 sweep 은 폐기되었다.
본 절은 기각 판정의 분석 도구로 유효성이 남은 lane-separation 자원
모델 (Theorem~\ref{thm:lane-separation}) 과 그 역방향 (misuse) 측정
증거만 보존한다.

\subsection{Theorem 1 — Lane Separation}
\label{subsec:thm-lane-separation}

\begin{theorem}[Lane Separation]
\label{thm:lane-separation}
두 lane $L_i, L_j$ 가 자원 벡터 $\mathbf{r}_i = (\rho_i^{\text{mem}},
\rho_i^{\text{alu}}, \rho_i^{\text{io}})$ 로 표현될 때, 두 lane 의 동시 작동
처리량은 다음 조건 하에서 \emph{가산}된다:
\begin{equation}
\mathbf{r}_i \cdot \mathbf{r}_j \le \kappa\,\|\mathbf{r}_i\|\,\|\mathbf{r}_j\|,
\quad \kappa = 0.3.
\label{eq:lane-sep}
\end{equation}
LHC 의 (DSA, AMX, NEO) 세 lane 은 측정상 $\kappa\!<\!0.18$ 을 모두 만족하므로
가산 가능하다.
\end{theorem}

\begin{proof}[증명 스케치]
DSA 의 dominant 자원은 host memory bus, AMX 는 vector ALU, NEO 는 pinned
DRAM $+$ PCIe. 각 lane 단독 측정 (Phase 3 microbench) 시 다른 lane 의 자원에
0.18 미만의 dot product 압력만 가한다. 따라서 식~(\ref{eq:lane-sep}) 의
$\kappa\!=\!0.3$ 안에 들어간다. 가산성은 Little's law $+$ 자원 보존에서 자동
유도된다.
\end{proof}

\paragraph{Misuse evidence (역의 측정).}
Theorem~\ref{thm:lane-separation} 의 \emph{역}을 측정으로 검증한다 --- LHC
infrastructure 의 5가지 anti-pattern (active-lane: AMX C3 force-every-step;
inactive-lane: DSA\_MIN$=$64, NUMA cross-socket, WQ-per-rank OFF, regime
detector OFF) $\times$ 본 baseline $\times$ 3 sweep $=$ 30 cell 측정에서,
\emph{active-lane misuse 만} paired Δ\% $=\!-92.5\%$ 의 dramatic penalty
를 일으켰다 (\S\ref{subsec:res-misuse}). 나머지 4 anti-pattern 은 GPU-saturated
regime 에서 gate 가 차단해 dead path 가 되어 noise band ($\pm 2\%$) 안에
머물렀다. 이는 식~(\ref{eq:lane-sep}) 의 $\kappa < 0.3$ 조건이 \emph{lane gate
정상 동작 시에만} 유효함을 보여준다 --- gate 가 빠진 active lane 은
$\kappa$ 가 가산 조건을 깨뜨려 superposition 이 무너진다.
